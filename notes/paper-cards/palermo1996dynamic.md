# Dynamic Data Partitioning for Distributed-Memory Multicomputers
**Catalog id:** `palermo1996dynamic`
**Citation:** Daniel J. Palermo, Eugene W. Hodges IV, and Prithviraj Banerjee. "Dynamic Data Partitioning for Distributed-Memory Multicomputers." Journal of Parallel and Distributed Computing 38, 158-175 (1996), article no. 0138. Record used: journal header and printed page numbers; no DOI printed.
**Paper type:** compiler-technique
**Access:** PDF supplied by the repository owner. Full text read (18 PDF pages, printed pp. 158-175). The text layer is present and readable with a few dropped letters. Figure graphics (graphs, plots, pseudo-code boxes) are not in the text layer; Tables I-III are extracted.
**Card status:** full-read

## Problem
A single static distribution can be a compromise when a program's access pattern changes between phases, as in a two-dimensional FFT that works along rows and then along columns (p. 158-159). The paper selects distributions that change over the run of a program, weighing the benefit of each phase's preferred layout against the cost of redistribution, and does so automatically (p. 158). The method extends PARADIGM's static partitioner (p. 158, 160-161).

## Input abstraction
The input is a serial program analyzed by Parafrase-2. Flow dependence information is weighted by communication cost to form a communication graph whose nodes are statements (p. 161-162). Phases are not supplied by the user; the program is decomposed recursively at statement boundaries (p. 162-164). The ADI2D and Shallow benchmarks were inlined, and a GOTO-formed loop was rewritten as an explicit loop because the framework does not handle unstructured code (p. 171).

## Target
Cost models are given for an Intel Paragon and a TMC CM-5, using measured startup and per-byte parameters for Transfer and Shift (p. 162, Table I). Table II estimates are for 32 processors (p. 165). Table III gives measured transpose times for 8 to 128 processors on both machines (p. 172).

## Data decomposition
Distributions are expressed per array dimension as BLOCK or *, over a two-dimensional abstract mesh. The static partitioner chooses the mesh shape and each array's layout (p. 165, 172-173). In ADI2D the selected layouts alternate between (*, BLOCK) and (BLOCK, *) (Table II). The Shallow benchmark uses only BLOCK distributions on an 8 by 4 mesh (p. 172).

## Computation mapping
The paper does not restate loop-level partitioning; it relies on the static partitioner, which fixes the distribution of each phase (p. 160-161). In the static ADI version, two recurrences are satisfied by software pipelining, and the pipeline granularity is chosen from compile-time estimates (p. 170). The dynamic ADI version uses data-parallel phases separated by transposes (p. 170).

## Communication generation
Redistribution between phases is generated as transposes, and transposes that occur at the same program point are aggregated into one message (p. 170). The redistribution cost is estimated for each edge of the phase transition graph (p. 165). Pipelined loops use a coarse-grain granularity chosen from the compile-time pipeline model (p. 170-171; Fig. 11).

## Compiler / runtime split
All phase decomposition, costing and selection happen at compile time. The phase tree is built by repeatedly cutting the communication graph at a maximal cut, and branch and bound accepts a split only if the summed estimated times of the two sub-phases improve (p. 163-164). The phase transition graph is then solved by a shortest-path search, implemented with Dijkstra's algorithm in O(V^2) time (p. 165). The final output is an MPI program generated by the prototype PARADIGM compiler (p. 173).

## Evaluation
ADI2D on a 512 by 512 problem is run on an Intel Paragon and a TMC CM-5, comparing fine-grain and coarse-grain static pipelining with the dynamic version with and without transpose aggregation (p. 169-171; Figs. 10-12). On the Paragon, the aggregated dynamic version is reported to be over 70 percent faster than fine-grain static and 60 percent faster than coarse-grain static. On the CM-5 it is more than twice as fast as fine-grain static, but beats coarse-grain only at extremely large processor counts (p. 170). For Shallow, the partitioner selects a static 2-D distribution with no redistribution. It matches the 1-D distribution at small processor counts and outperforms it by up to 1.6 times on the Paragon and 2.7 times on the CM-5 at larger counts (p. 171-173; Fig. 14).

## Principal limitation
As the paper states it: the static pipeline cost model is very conservative, which is why a dynamic scheme was chosen for ADI on both machines (p. 170); cut windows are resolved by always taking the earliest cut point (p. 164); and the hierarchical component affinity graph is not implemented, so interprocedural partitioning is future work (p. 169).
our observation: The Shallow experiment needed hand loop distribution and hand removal of copy loops (p. 173), so its reported times include manual changes.

## Relationship to earlier / later work
- The method extends the static partitioning algorithm of PARADIGM (refs. 14, 16) and its cost estimation (ref. 15), and builds on the authors' earlier dynamic selection paper (ref. 27) (p. 158, 161).
- Anderson and Lam (ref. 1) show that dynamic decomposition is NP-hard and use a greedy heuristic on a communication graph (p. 160).
- Bixby, Kennedy and Kremer (ref. 5) and Kremer (ref. 23) formulate phase selection as 0-1 integer programming; Kennedy and Kremer (ref. 24) give a dynamic programming alternative; Garcia et al. (ref. 12) follow the 0-1 approach (p. 160, 165-166).
- Hudak and Abraham (refs. 18, 19) insert remapping points; Sheffler et al. (ref. 34) apply graph contraction to the alignment-distribution graph; Chapman, Fahringer and Zima (ref. 6) and Chatterjee et al. (ref. 8) are discussed as prediction and alignment approaches (p. 160-161).
- The authors contrast their statement-level phase boundaries with the operational phase definition of Bixby et al. (ref. 5) (p. 160, 165-166).
- Kennedy and Kremer (ref. 21) predicted a one-dimensional column-wise block distribution for Shallow (p. 173).
- The pipeline cost model is from the authors' earlier work (ref. 28), and redistribution costs are estimated following Ramaswamy and Banerjee (ref. 31) (p. 165, 170).
- Future work is named for the hierarchical affinity graph, interprocedural analysis, and statement reordering (p. 169, 174).

## Open questions for the survey
- The authors say a more accurate pipeline model would have selected a static scheme on the CM-5 (p. 170). Do later systems in this set adopt pipeline cost models, and does the static-versus-dynamic choice change under them?
- Statement reordering and loop distribution could reduce redistribution (p. 170, footnote 9; p. 174). Did later work in this set adopt them?
- Redistribution across procedure boundaries is listed as future work (p. 174). Which later systems in the set handle it?
